# Архитектура

## Конвейер
`orchestrator.analyze` → `phrase_planner.make_plan` → `orchestrator.realize` → `orchestrator.build_score` → запись MIDI (звучащий строй) + микс + выравнивание громкости → `toWrittenPitch` → запись MusicXML (транспонированные партии) → `validator.check_score`.

## Командная строка
`python src/orchestrator.py <вход.mid|.musicxml> <путь_без_расширения> [off|full] [plan.json]`
Создаёт: `<путь>.mid`, `<путь>.musicxml`, `<путь>_plan.json`, `<путь>_report.json`.
`off` (по умолчанию): рояль заменён оркестром. `full`: рояль остаётся (мутно, не рекомендуется).

## Анализ (`analyze`)
- Берёт такты из первой партии (учитывает смену размера), все смены темпа (карта темпов с абсолютными смещениями).
- Мелодия: верхняя линия партии с самой высокой средней высотой, с реальным ритмом.
- Гармония: окна по доле, выровненные по тактам; бас = нижняя нота окна; до двух внутренних голосов выбираются из самых весомых звуков окна (ноты аккомпанемента весят вдвое).
- Фигурация (`meta["fig"]`): ноты левой руки выше баса окна (арпеджио).

## Карта фраз и план (`phrase_planner`)
Границы фраз: оценка после каждого такта (тишина мелодии в конце такта, долгая последняя нота, вход или уход мелодии, смена размера, замедление темпа, слабый метрический приор), порог 3, фразы 2–8 тактов.
Тип фразы: `intro` (нет мелодии), `run` (≥3 нот мелодии на долю), `figuration` (≥1.2 нот фигурации на долю), `lyric`.
Кульминация: самая высокая фраза длиной ≥3 такта.
Формат плана: `phrases[]` с полями `id`, `bars` [первый, последний, нумерация с 1], `kind`, `climax`, `color`, `level` (mp|mf|f), роли `melody`, `inner1`, `inner2`, `bass`, `figuration`: списки `[инструмент, сдвиг_в_полутонах, доля_фразы_для_вступления 0..1]`, и `why`. План можно править вручную и подавать четвёртым аргументом.

## Реализация
- Роли → инструменты по плану; ноты вне диапазона сдвигаются на октаву поодиночке (счётчик `octave_shifts` в отчёте).
- `repair_fifths`: исправляет параллельные квинты, меняя только внутренние голоса.
- `merge_sustains`: повторы внутренних голосов объединяются в длинные ноты.
- `enforce_breath`: убирает такты внутреннего голоса, чтобы дать духовым паузу (мелодию не трогает).
- Громкость нот: уровень фразы + смещение по роли (melody +14, inner −14, bass −6, figuration −10); MIDI-микс: панорама, реверберация, выравнивание инструментов при одинаковой силе нажатия.
- MusicXML пишется в транспонированном виде (кларнет in B♭, валторна in F, контрабас на октаву выше); MIDI остаётся в звучащем строе.

## Валидатор (`validator.check_score`)
HM32 (ошибка): параллельные квинты, в любую сторону. HM05: параллельные октавы между скрипками (предупреждение; в классике они обычны). G01: диапазоны (приблизительные). QX01: монотонность (повторы коротких нот). QX02: нет динамики. QX03: транспозиция объявлена. QX04: духовые без паузы дольше 16 долей. QX05: плотность дублирования по долям выше 1,35 (квартеты классиков дают в среднем 1,06). QX06: инструмент без нот. QX07: слишком быстрые ноты для контрабаса, валторны, фагота, виолончели. QX08: число играющих инструментов скачет больше чем на 4 между тактами.
В файле правил `src/orchestration_rules.json` реализована в коде лишь часть правил (перечислены выше). Остальные описывают принципы, которым следует планировщик по замыслу, но код их не проверяет.

## Источники данных
Правила: Римский-Корсаков, главы I–IV (пересказ, Project Gutenberg #33900). Статистика классики: 46 струнных квартетов из корпуса библиотеки music21 (параллельные квинты 0,6–1,2% движений в одном направлении, октавы 13–25%).
